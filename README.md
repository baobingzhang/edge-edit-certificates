# Exact Edge-Edit Certificates for One-Layer Mean-Aggregation Graph Models

Code, raw results and verification scripts for the paper

> **Exact Edge-Edit Certificates for One-Layer Mean-Aggregation Graph Models: Predictions, Attributions, and the Value of the Graph**
> Baobing Zhang, Wanxin Sui. Submitted to *Neural Networks*.

The repository is organised so that every number in the paper can be checked at three levels of effort, from
one minute on a laptop to a full rerun on a GPU. All numbers, tables and figures of the paper are generated by
scripts from the per-split result files shipped in `results/`; nothing is typed in by hand.

## What the paper shows

**Method.** For a one-layer graph model whose node score uses the graph only through a *mean of neighbour scores*,

```
logit_i,c = f_c(x_i) + mean_{u in N(i)} g_c(x_u)
```

the worst set of edge edits (insertions and deletions, global budget *b*) can be found **exactly by sorting**:
only edges at node *i* matter, and for each split of the budget into *p* deletions and *q* insertions the worst
choice deletes the *p* largest and inserts the *q* smallest neighbour scores. For additive members (CertGAM) the
same argument certifies **feature attributions**, and certified training is **convex**. A degree-shrinkage
aggregator (ShrinkGAM) keeps the certificate exact, and an enumeration argument gives an exact single-edit
certificate for **two-layer GraphSAGE** with mean aggregation.

**Main finding.** Graph-free models cannot be affected by edge edits, and they turn out to be very hard to beat:

| Finding (one edge edit, *b* = 1) | Number | Source in this repo |
|---|---|---|
| Certified graph models below the validation-selected graph-free reference | 72 of 77 model–dataset cells | `make_figs.py` → Fig. 1 |
| Even the best certified model per dataset (selected on test, optimistic) beats it only on | Cora, Texas, roman-empire | Fig. 1, last row |
| Split-level consistency: CertGAM-R / two-layer SAGE below the reference on | 59 of 63 / 63 of 63 split–dataset pairs | Fig. S1 |
| Certified training lowers the neighbour share of the score on | 11 of 11 datasets | Fig. 3 |
| Real edits recomputed from scratch to try to break a certificate | 2,336,580, none successful | Fig. S2 |
| Certified π-PPNP (prior work, exact single-toggle certificate) below the reference on | 6 of 6 graphs with ≤ 8000 nodes | `results/s09`, H18e |

The break-even attack rate π⋆ (how often a node must be attacked before using the graph stops paying) is
clearly positive only on Cora, and low-degree nodes dominate the fragility of mean aggregation.

## Installation

Python 3.12 and a recent PyTorch with PyTorch Geometric. The versions used for the paper are pinned in
`requirements.txt`.

```bash
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt            # pick the torch build that matches your CUDA, see pytorch.org
```

Datasets (Cora, CiteSeer, PubMed, Texas, Wisconsin, Cornell, Actor, roman-empire, amazon-ratings, minesweeper,
tolokers; about 270 MB) are downloaded automatically by PyTorch Geometric into `data/` on first use.

The scripts call `python`; set `PY=/path/to/python` to use another interpreter.

## Quick start: certify a model in seconds

```bash
python scripts/quickstart.py Texas 3        # dataset and split; runs on CPU in a few seconds
```

It trains CertGAM with the configuration frozen on validation data, certifies every test node exactly against
1, 2, 3, 5 and 10 edits, and prints the graph-free reference next to it:

```
Texas, split 3: CertGAM {'K': 2, 'theta': 1.0, 'lam': 0.0001}, 37 test nodes
  clean accuracy           86.5
  certified,  1 edit(s)    10.8
  certified,  2 edit(s)     2.7
  ...
  neighbour share of score variation 0.48
  graph-free reference (mlp, mean over splits 3-9): 77.2 -- edge edits cannot change it
```

The certified values are identical to the shipped GPU result for this split (`results/s03/Texas__certgam.json`);
the clean accuracy on CPU differed by one of 37 test nodes in our check (86.5 against 83.8).

The core API in three calls:

```python
import cert, exp
g, masks = exp.splits("Texas")                              # graph and the 10 fixed splits
m = cert.NeighbourGAM(g, int(g.y.max()) + 1, K=2, theta=1.0)
cert.fit(m, masks[0][:, 3], g.y, 1e-4)                      # convex ridge training
nodes = masks[2][:, 3].nonzero().flatten().numpy()         # test nodes of split 3
pred, radius = cert.radii(m, nodes, [1, 2, 3, 5, 10])       # exact certified radius per node
```

## Verifying the paper

All three levels work on a scratch copy in `work/`, so the shipped results are never overwritten.

| Level | Command | Hardware | Time (measured) | What it shows |
|---|---|---|---|---|
| 1 | `bash scripts/verify_paper.sh` | CPU | ~1 min (+ dataset download) | every verdict, number, table and figure follows from the shipped per-split results |
| 2 | `bash scripts/run_checks.sh` | CPU; GPU for 5 of 10 checks | ~10 min on an RTX 3070 Laptop | the certificates are exact and the theorems hold on test instances |
| 3 | `bash scripts/rerun.sh RESULT COMMAND...` | GPU | 20 s to hours per run | a shipped result is reproduced by rerunning it |

### Level 1 - from results to paper

```bash
bash scripts/verify_paper.sh
```

1. reruns the pre-specified tests (`judge.py`, `analysis.py`, `sensitivity.py`, `judge5.py`, `judge7.py`,
   `judge8.py`) on the per-split results and checks that the six verdict files are identical to the shipped ones;
2. runs `make_paper.py` and `make_figs.py`, which write all tables, figures and a macro for every number used in
   the text; `make_figs.py` also asserts that its key quantities agree with the main tables and stops otherwise;
3. compares the 20 generated LaTeX files with `expected/gen/`, the files compiled into the paper.

Expected output (abridged):

```
SAME    verdict.json   ...   SAME    verdict8.json
PASS
PASS: 20 generated files identical; figures in work/paper/figs/
```

### Level 2 - correctness gates

```bash
bash scripts/run_checks.sh
```

| Check | What would make it fail |
|---|---|
| `verify_theory.py` | a sampled instance (2000 random graphs per part) violating either bound of the filter-stability theorem |
| `verify_shrink.py` | a single edit moving the shrunk neighbour term by more than the bound of Prop. 3 |
| `test_cert.py` | a real edit set flipping a "certified" node, a bound looser than brute force, a non-convex objective |
| `test_smooth.py` | an invalid smoothing certificate for the baselines |
| `test_fallback.py` | an edit within budget changing a certified output of the composite classifier |
| `test_cert2.py` (GPU) | the two-layer SAGE certificate disagreeing with recomputing the whole model on every edited graph |
| `test_shrink.py` (GPU) | a ShrinkGAM certificate that is not exact for some kappa |
| `test_ppr_exact.py` (GPU) | the Woodbury single-toggle certificate of pi-PPNP disagreeing with brute force |
| `test_ppr_chunk.py` (GPU) | the chunked implementation depending on the chunk size |
| `test_ppr_fix.py` (GPU) | the memory fixes changing what the robust pi-PPNP losses optimise |

Expected output: `== 10 passed, 0 failed, 0 skipped` (GPU checks are reported as skipped without CUDA).

### Level 3 - rerun an experiment

```bash
bash scripts/rerun.sh s03/Cora__certgam.json      exp.py s03 Cora certgam      # CertGAM, splits 3-9
bash scripts/rerun.sh s03/Texas__certrob.json     exp.py s03 Texas certrob     # CertGAM-R, ~1 min
bash scripts/rerun.sh s05/Texas__sage2.json       exp6.py Texas                # two-layer SAGE, ~20 s
bash scripts/rerun.sh s07/Texas__shrink.json      exp8.py Texas                # ShrinkGAM-R
bash scripts/rerun.sh s09/Texas__pippnp_exact.json exp10e.py Texas             # pi-PPNP, exact certificate
```

The rerun uses the configuration frozen in `results/s02` (or selects it again on split 0 where the runner does
so) and prints the per-model means over splits of accuracy and certified accuracy at b = 1, shipped against
rerun, with a tolerance of two points (`--tol` in `scripts/compare_json.py`). Two runs we checked:

```
s03/Texas__certrob.json   accuracy 79.54 -> 79.54   certified b=1 78.76 -> 78.76   PASS
s05/Texas__sage2.json     sage     86.10 -> 85.71             11.58 -> 12.36
                          sageaug  80.69 -> 80.69             44.40 -> 44.40   PASS
```

## Running the experiments from scratch

The runners are the exact sequence behind the paper; each writes one JSON file per dataset and model and
skips files that already exist. Run them in a fresh clone (or delete the corresponding `results/` files first).

| Stage | Script | Content | GPU time in the paper |
|---|---|---|---|
| S02 | `code/s02.sh` | configuration selection on validation data of split 0 | 8.4 h |
| S03 | `code/s03.sh` | frozen configurations on splits 3–9, 14 dataset variants × 11 models (needs `results/s02/FROZEN.sha256`) | 18.9 h |
| S04 | `code/s04.sh` | CertMLP, Smooth-SAGE, degree and case-study runs | 6.8 h |
| S05 | `code/s05.sh` | two-layer SAGE with exact b = 1 certificates | 1.6 h |
| S06 | `code/s06.sh` | SAGE-adv, exploratory | 0.6 h |
| S07/S08 | `code/s07.sh` | ShrinkGAM-R, then SAGE-adv × 4 | 4.2 h |
| S09 | `code/s09.sh`, `code/s09b.sh` | π-PPNP with exact and local certificates | 4.1 h |

Total about 45 GPU hours on one NVIDIA RTX 3070 Laptop GPU (8 GB). Runs that exceed GPU memory are recorded as
`"status": "OOM"` or `"error"` and appear as missing entries in the paper rather than being dropped silently.

## Pre-registration and analysis rules

`prereg/` holds the analysis plans (`PLAN.html`, `PLAN_v2.html` and addenda v3–v8c). Hypotheses, thresholds and
the analysis code were fixed in these plans before the corresponding confirmatory runs; SHA-256 hashes of the
two main plans are in `prereg/*.sha256`, and hashes of the code at each freeze point in `results/code_at_*.sha256`.
Changes to frozen files are recorded as diffs: `results/judge_change.diff` (against `results/judge_at_freeze.py`)
and `results/smooth_change.diff` (docstring only).

Rules used throughout:

* configurations are selected on the validation set of split 0 only; splits 3–9 are used for testing;
* the selection score is 0.5 · clean accuracy + 0.5 · certified accuracy at b = 1;
* the graph-free reference is chosen on validation data among the graph-free models;
* failed runs (out of memory, errors) are reported, never replaced.

## Result file format

Each `results/sXX/DATASET__MODEL.json` has `ds`, `model`, `status` (`ok`, `OOM`, `error`, `TIMEOUT`), the
selected `cfg`, and `rows`, one entry per split with, depending on the model,

* `acc` / `metric`: clean accuracy (and ROC-AUC where it is the convention);
* `cert` (`{"1": ..., "2": ..., "3": ..., "5": ..., "10": ...}`) or `cert1`: certified accuracy;
* `graph_share`: neighbour share of the score variation;
* `nodes`, `deg`, `correct`, `robust` / `rad`: per-node records (degree, correctness, certified radius);
* `fuzz_tried`, `fuzz_broken`, `attack_tried`, `broken`: real edits recomputed to try to break certificates;
* `train_sec`, `sec_per_node`, `peak_gb`: compute.

## Determinism and known differences

* Level 1 and level 2 are deterministic: level 1 reproduces the verdict files and the generated LaTeX exactly
  (figures are regenerated but not compared byte for byte, since PDF files carry timestamps).
* Level 3 reruns of the convex models (CertGAM, CertGAM-R) reproduced the shipped means exactly in our check;
  neural models trained with SGD on GPU (two-layer SAGE, π-PPNP, baselines) vary within about a point because
  CUDA kernels are not deterministic.
* On CPU, results can differ from the GPU runs by single test nodes (see the quick start).
* The S02/S03 runs were made with the code hashed in `results/code_at_s03.sha256`; later stages each record
  their own hash.

## What is not included

* **The G-NAMRFF authors' code.** `results/repro/cora_table3.json` and `logs/s04.log` come from running the
  authors' released script unmodified; that script is not redistributed here. Our own re-implementation is
  `gam.GNAMRFF`.
* **The official π-PPNP code** of Bojchevski and Günnemann (2019), against which `test_ppr.py` compared our
  implementation (`results/g10.json`); that test is omitted because it needs the external code.
* **Datasets**, which PyTorch Geometric downloads from their original sources.
* Orchestration scripts of the original runs (job queues, watchdogs) that do not affect results.
